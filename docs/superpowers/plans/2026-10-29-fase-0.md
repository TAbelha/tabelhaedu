### Global Constraints

- **Versões:**
  - `@sveltejs/kit ^3.1`, `svelte ^5.57`, `vite ^8`;
  - `typescript ^6`. **Não usar 7**, porque o Kit 3 exige ^6;
  - `@sveltejs/adapter-cloudflare ^8`, `wrangler ^4.155`, `tailwindcss ^4.3`, `shadcn-svelte 1.7.x`;
  - `better-auth ^1.7.14`;
  - `drizzle-orm ^0.45`, `drizzle-kit ^0.31`. **Não usar a 1.0 rc.**
- **Ambiente:** Node >= 22.17, CI com Node 24, gerenciador bun, `bun.lock` versionado.
- **Cola de APIs do Kit 3** (o ESLint garante):
  - `#lib/...` com extensão `.js`, como na doc do Better Auth. Seguir o que o scaffold gerar;
  - `$app/env` (`building`), não `$app/environment`;
  - `$app/state`, não `$app/stores`;
  - `error(status, 'texto')`;
  - config do Kit dentro de `sveltekit({...})` no `vite.config.ts`, porque não existe `svelte.config.js`;
  - `Handle`/`sequence` vêm de `@sveltejs/kit/hooks`.
- **Bindings:** `import { env } from 'cloudflare:workers'` **só** em `src/lib/server/platform.ts`.
- **Imports relativos (sem `#lib`):** obrigatórios nos módulos que o `drizzle-kit` e a CLI do Better Auth carregam fora do Vite:
  - `src/lib/server/db/schema/*`;
  - `src/lib/server/auth/options.ts`;
  - `src/lib/permissions.ts`;
  - `auth.cli.ts`.
- **D1:**
  - nunca `db.transaction`;
  - escrita em várias tabelas usa `db.batch([...])`;
  - todo insert em lote passa por `chunkRows` (<= 100 parâmetros);
  - migrações são só de acréscimo depois do primeiro `--remote`.
- **Repositórios:**
  - sempre recebem `orgId`;
  - um id de outra org gera `NotFoundError`, que vira 404, nunca 403.
- **`{@html}`:** só no `rich-text.svelte` (HTML do nosso pipeline). O tema entra via `transformPageChunk`.
- **Tipos de dado:**
  - datas de calendário: `text` `YYYY-MM-DD`;
  - instantes: `integer` com `mode: 'timestamp_ms'`;
  - ids das tabelas do app: `crypto.randomUUID()`.
- **Idioma:**
  - comentários em inglês;
  - textos de UI, README e docs em PT-BR (README em EN + PT-BR, pela skill `tabelha-readme`);
  - rotas de página em PT-BR, `/api/*` em inglês.
- **Commits:** sem linha de coautoria de IA em commit nem PR.
- **Conteúdo proibido:**
  - nada de código, nomes de clientes, gateways ou detalhes internos da plataforma de referência;
  - nada do material do cursinho voluntário.
- **Ciclo por task:** teste que falha, depois implementação mínima, teste passando e commit.
- **Verificação padrão de cada task:**
  ```
  bun run check && bun run lint && bun run test && bun run build
  ```

### Review Focus

1. **Isolamento entre orgs.** Um id de outra org na URL ou no form tem que dar 404. Fica preso em teste `cross-org` em todo repositório: o primeiro é o `removeDomain` (Task 4), e depois um por repo em cada fase.
2. **Prazo e retomada do simulado:**
   - recarregar no meio da prova retoma com o tempo certo;
   - resposta depois do prazo + 30 s é rejeitada;
   - tentativa abandonada fecha no prazo;
   - horário digitado em BRT vira o UTC certo.
   Testes de `timing` (Fase 5) e `datetime` (Fase 4).
3. **Vazamento de gabarito.** `JSON.stringify` do load da prova e da prévia não pode conter `answerKey` nem `solution` antes da divulgação (Fases 4 e 5).
4. **Texto brasileiro:**
   - "R$ 1.500,00 e R$ 2.000,00" não vira fórmula;
   - LaTeX quebrado não derruba o render;

   Teste do `render` (Fase 3).
5. **Limites do D1.** Template ENEM com cerca de 250 nós, importação de 300 alunos e recálculo com 100 tentativas não podem estourar os 100 parâmetros. Testes de `chunkRows` (0.2), `applyTemplate` (Fase 1), `importRoster` (Fase 5) e `regradeExam` (Fase 5).

## 6. Riscos

1. **Plano do Workers.** No Free (10 ms de CPU), o scrypt do Better Auth tende a estourar e dar erro 1102. É preciso confirmar o plano antes do primeiro deploy. Se for Free, a saída é implementar `emailAndPassword.password.{hash,verify}` com PBKDF2 do WebCrypto, ou assinar o Paid.
2. **Kit 3 com 4 semanas de vida.** Mitigação: o ESLint barra a API antiga e o Task 1 tem um ponto de saída.
3. **Sem e-mail.** O aluno que esquecer a senha fica sem saída no v0. Além disso, a matrícula por lista é ativada por e-mail não verificado (risco baixo num cursinho, mas real).
4. **D1 sem transações.** Tudo que precisa ser atômico usa `batch`. Os testes rodam em libsql, que aceitaria `transaction`, por isso a regra do ESLint é obrigatória.
5. **Drizzle 1.0.** A doc já empurra o RC e o layout de migração pode mudar. Ficar no 0.45/0.31 até a 1.0 virar `latest`.
